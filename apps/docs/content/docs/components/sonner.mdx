Mount `<Toaster />` once at the root of your application (e.g. the root layout)
and call `toast()` from anywhere in the component tree to fire a notification.
The component reads the active `next-themes` color scheme automatically and
applies design-system CSS custom properties for colors, border-radius, and icons.

## Usage

```tsx twoslash
import { toast } from "sonner";
import { Toaster } from "@workspace/ui/components/sonner";

export function App() {
  return (
    <>
      <Toaster />
      <button onClick={() => toast("File saved successfully.")}>
        Show toast
      </button>
    </>
  );
}
```

## Guidelines

**Do**

- Render `<Toaster />` once at the top of the component tree — not inside
  individual components.
- Enable `richColors` when semantic color helps distinguish message severity.
- Keep toast messages to one sentence maximum.
- Provide an action only when a genuinely reversible operation just occurred.

**Don't**

- Use toasts for critical errors that require user attention — use a dialog
  instead.
- Stack multiple `<Toaster />` instances; Sonner manages its own portal.
- Rely on toasts for form validation feedback — place errors inline with the
  field.

## Accessibility

- Toasts are rendered in a live region and announced to screen readers
  automatically by Sonner.
- Ensure toast messages are meaningful without relying on color alone — use
  descriptive text alongside semantic variants.
- Avoid setting `duration` so short that users cannot read the message; the
  default of 4 000 ms is a safe minimum.
