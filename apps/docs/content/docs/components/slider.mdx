Use a slider for continuous values where approximate selection is acceptable —
volume, zoom level, opacity, or price range filters. For discrete values or when
the user needs exact input, prefer a number `Input` instead.

Built on Base UI's `Slider` primitive. Pass a single-element array to
`defaultValue` for one thumb, or two elements for a range. Thumb count is inferred
from the array length automatically.

## Usage

```tsx twoslash
import { Slider } from "@workspace/ui/components/slider";

export function Example() {
  return <Slider defaultValue={[25]} min={0} max={100} className="w-64" />;
}
```

## Guidelines

**Do**

- Always label the slider with a visible label or `aria-label` describing what is
  being controlled.
- Show the current value numerically when precision matters.
- Use `step` to limit choices to valid values when the domain is discrete.

**Don't**

- Use a slider when the user needs to type an exact value — prefer a number input.
- Omit min/max labels for range sliders; users need to understand the scale.
- Place a vertical slider inside a horizontally scrolling container.

## Accessibility

- Each thumb renders with `role="slider"` and exposes `aria-valuenow`,
  `aria-valuemin`, `aria-valuemax`, and `aria-orientation`.
- <kbd>ArrowLeft</kbd> / <kbd>ArrowRight</kbd> (horizontal) or <kbd>ArrowUp</kbd>
  / <kbd>ArrowDown</kbd> (vertical) move the focused thumb by one step.
- <kbd>Home</kbd> and <kbd>End</kbd> jump the focused thumb to the minimum and
  maximum values.
- Provide an `aria-label` or a visible label associated via `aria-labelledby` so
  screen readers can announce what the slider controls.
