Use a sheet for navigation menus, settings drawers, and supplemental content that
should remain in context alongside the main page. Choose `side` to control which
edge the panel slides from.

Built on Base UI's `Dialog` primitive, so it shares the same focus trapping,
scroll locking, and ARIA semantics as `Dialog`. `SheetContent` renders the
overlay and portal automatically.

## Usage

```tsx twoslash
import { Button } from "@workspace/ui/components/button";
import {
  Sheet,
  SheetContent,
  SheetHeader,
  SheetTitle,
  SheetDescription,
  SheetTrigger,
} from "@workspace/ui/components/sheet";

export function Example() {
  return (
    <Sheet>
      <SheetTrigger render={<Button variant="outline" />}>Open</SheetTrigger>
      <SheetContent>
        <SheetHeader>
          <SheetTitle>Edit profile</SheetTitle>
          <SheetDescription>Make changes to your profile.</SheetDescription>
        </SheetHeader>
      </SheetContent>
    </Sheet>
  );
}
```

## Guidelines

**Do**

- Write a `SheetTitle` and `SheetDescription` — they wire up ARIA and are
  announced by screen readers on open.
- Use `SheetFooter` for primary actions so they stay consistently placed.

**Don't**

- Use a sheet for short confirmation prompts — a `Dialog` is more appropriate.
- Nest a sheet inside another sheet.

## Accessibility

- Renders `role="dialog"` with `aria-modal="true"`, trapping focus while open.
- `SheetTitle` and `SheetDescription` are automatically linked via `aria-labelledby`
  and `aria-describedby`.
- <kbd>Escape</kbd> closes the sheet and returns focus to the trigger.
- A built-in close button is included by default; pass `showCloseButton={false}` to
  suppress it when you provide custom dismiss controls.
