Use a popover for secondary content tied to a specific trigger — settings panels,
dimension controls, or quick previews — when a full dialog would be too disruptive.
It does not disable the rest of the page.

Built on Base UI's `Popover` primitive. Compose `PopoverTrigger` with `PopoverContent`,
and optionally include `PopoverHeader`, `PopoverTitle`, and `PopoverDescription` for
structured, accessible content.

## Usage

```tsx twoslash
import { Button } from "@workspace/ui/components/button";
import {
  Popover,
  PopoverContent,
  PopoverHeader,
  PopoverTitle,
  PopoverDescription,
  PopoverTrigger,
} from "@workspace/ui/components/popover";

export function Example() {
  return (
    <Popover>
      <PopoverTrigger render={<Button variant="outline" />}>Open</PopoverTrigger>
      <PopoverContent>
        <PopoverHeader>
          <PopoverTitle>Settings</PopoverTitle>
          <PopoverDescription>Adjust your preferences.</PopoverDescription>
        </PopoverHeader>
      </PopoverContent>
    </Popover>
  );
}
```

## Guidelines

**Do**

- Use a popover for secondary, non-blocking content tied to a trigger.
- Give it a title and description so the popup is self-explanatory.
- Reserve `modal` for cases that genuinely require focus trapping.

**Don't**

- Use a popover for critical, must-acknowledge decisions — use a `Dialog` instead.
- Pack long-form or scrolling content into a popover.

## Accessibility

- The floating panel receives `role="dialog"` and is linked to the trigger via
  `aria-controls`.
- `PopoverTitle` and `PopoverDescription` are wired to the popup via ARIA for screen
  readers automatically.
- <kbd>Escape</kbd> closes the popover and returns focus to the trigger.
- Focus is managed by Base UI; the trigger keeps `aria-expanded` in sync with the
  open state.
